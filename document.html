Documentation

A quoi sert une documentation

La documentation est essentielle car elle permet de transmettre un projet à d’autres personnes afin que celles-ci puissent continuer à travailler sur ce projet. La documentation doit permettre de comprendre et de réaliser toutes les étapes d’un projet.

Comment bien rédiger sa documentation

Une bonne documentation doit permettre à une personne extérieure au projet de pouvoir suivre toutes les étapes décrites en autonomie. Pour cela, il est important d’y renseigner les problèmes rencontrés et les solutions trouvées pour y remédier.

Structure d’une documentation

Les branches rolling et gh-pages dans une documentation hébergée par GitHub ont des objectifs différents.

  1. Branch rolling : Cette branche est souvent utilisée pour des versions de développement continues ou instables. Elle contient généralement les dernières modifications qui sont en cours de développement. Les utilisateurs peuvent y accéder pour tester les dernières fonctionnalités ou changements avant qu’ils ne soient intégrés à la branche principale (comme main ou master). Cela permet d’avoir une version toujours en développement (rolling release) pour les utilisateurs avancés ou les contributeurs, sans affecter la version stable de la documentation.

  2. Branch gh-pages : Cette branche est spécifiquement utilisée pour héberger des sites web statiques via GitHub Pages. Lorsqu’une documentation est déployée sur GitHub Pages, elle est généralement placée dans la branche gh-pages. Cela permet de rendre le contenu accessible sous un format HTML sur une URL spécifique. Elle contient souvent les fichiers pour générer de la documentation prêts à être publiés en ligne.

  3. Sphinx : Le sphinx permet dans la création de notre documentation de convertir les fichiers au format rst en pages au format html.
